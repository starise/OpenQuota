# Domain documentation

OpenQuota uses a single domain context. Before exploring a design or
implementation, read the root `GLOSSARY.md` and any relevant decisions in
`docs/adr/` when they exist. Use glossary terms in specs, issues, and tests.
Flag any proposed change that conflicts with an existing decision.

Use the domain-modeling skill to add glossary terms and architecture decision
records when decisions are made. Keep implementation details in the relevant
spec or decision record.
